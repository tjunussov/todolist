## Context

Один статический `index.html`, без сборки. Нужно решить: как подключить Vue, как структурировать данные, как синхронизировать с `localStorage`.

## Goals / Non-Goals

- Goal: рабочий todo-лист, открываемый напрямую в браузере (`file://` или любой статик-хостинг), без шага сборки.
- Goal: данные переживают перезагрузку/закрытие вкладки.
- Non-Goal: сервер, бэкенд, многопользовательский режим, синхронизация между устройствами.
- Non-Goal: Quasar/роутер/стейт-менеджер — оверкилл для одного списка.

## Decisions

### Подключение Vue
Vue 3 global/UMD build через `<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>` (CDN, pinned major `@3`). В global-сборке нет SFC-компилятора для `<script setup>` без шага сборки, поэтому компонент пишется как обычный `<script>` с `const { createApp, ref, watch } = Vue` и `createApp({ setup() {...}, template: ... })` — либо inline-template в самом HTML (`#app` разметка + `template: '#app'`), что проще читать. Выбор: inline-template в DOM, т.к. Pug/SFC тут недоступны (UMD, без сборки).

### Модель данных
Массив объектов `{ id, text, done }` в одном `ref([])`. `id` — `Date.now()` + счётчик-коллизия не критична для локального однопользовательского списка (`ponytail`: `crypto.randomUUID()` если нужна надёжность, но `Date.now()` достаточно — не над чем размышлять в однопоточном UI-коде).

### Персист в localStorage
Один ключ `tjtodo-1-tasks`, значение — `JSON.stringify(tasks.value)`. Запись через `watch(tasks, save, { deep: true })` — срабатывает на add/toggle/remove одинаково, не нужно дублировать вызов `save()` в каждом методе. Чтение — при инициализации `ref(JSON.parse(localStorage.getItem(key) || '[]'))`, с `try/catch` на случай битого JSON (единственная точка входа недоверенных данных — то, что лежало в localStorage до этого запуска).

### Структура файла
Всё в одном `index.html`: `<style>` в `<head>`, разметка в `<body>`, `<script>` в конце `<body>` (после разметки, чтобы `#app` существовал к моменту `createApp().mount()`).

## Risks / Trade-offs

- CDN-зависимость (unpkg) — если недоступен офлайн, страница не оживёт. Принято: задача не требует офлайн-режима.
- `localStorage` — per-origin: при открытии файла через `file://` данные привязаны к этому пути/браузеру, не синхронизируются между вкладками разных браузеров. Ожидаемо для однопользовательского локального инструмента.
